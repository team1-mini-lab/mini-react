# ADR-0002: 실제 DOM → Virtual DOM 변환 방식과 공백 글자 노드 처리 규칙

## Context and Problem Statement

시스템은 실제 영역의 브라우저 DOM 요소를 Virtual DOM 객체 트리로 변환해야 합니다. Virtual DOM 객체는 노드 종류, 속성, 자식 노드 정보를 표현해야 하며, Phase 2에서 그대로 재사용할 수 있어야 합니다.

이 변환 결과는 세 곳에서 쓰입니다.
- 로드 시 테스트 영역 렌더링
- Patch 시 Diff의 비교 대상
- State History에 저장되는 기록

변환 함수는 루트 요소(`div#app`) **하나**를 입력으로 받지만, 결과에는 모든 자손이 부모-자식 관계를 유지한 채 들어 있어야 합니다. 그래서 다음 두 가지를 정해야 합니다.

1. 트리 전체를 어떤 방식으로 변환할 것인가
2. **공백 전용 글자 노드를 어떻게 표현할 것인가**

두 번째가 문제가 되는 이유는 이렇습니다. 브라우저는 HTML의 줄바꿈과 들여쓰기도 글자 노드로 만듭니다. 아래 두 HTML은 화면에서 같아 보이지만, Chrome에서 `document.getElementById("app").childNodes.length`를 실행하면 각각 **5**와 **2**가 나옵니다.

```html
<div id="app">
  <h1>장바구니</h1>
  <p class="price">3000원</p>
</div>
```
```html
<div id="app"><h1>장바구니</h1><p class="price">3000원</p></div>
```

- 공백 노드를 그대로 두면, 화면에 영향이 없는 들여쓰기 변경에도 Diff가 변경을 찾아 Patch합니다.
- 공백 노드를 버리면, `<b>안녕</b> <i>하세요</i>`의 띄어쓰기가 사라져 화면이 달라집니다.

## Decision Drivers

- **화면 동일성**: 테스트 영역과 실제 영역이 화면에서 같게 보여야 한다.
- **최소 변경**: 화면에 영향이 없는 변경에 Diff/Patch가 반응하지 않아야 한다.
- **측정 가능성**: 두 영역이 같은지를 코드로 확인할 수 있어야 한다.
- **견고성**: 자식 없는 요소, 깊게 중첩된 구조에서도 변환이 성립해야 한다.
- **Phase 2 재사용**: Phase 2의 컴포넌트가 같은 노드 모양을 만들어 Diff/Patch에 그대로 넘길 수 있어야 한다.

## Considered Options

- 선택지 1: 공백 노드를 실제 DOM과 똑같이 보존한다
- 선택지 2: 공백 전용 글자 노드를 버린다
- 선택지 3: 줄바꿈이 포함된 공백 노드만 버리고, 같은 줄 공백은 남긴다
- 선택지 4: 연속 공백 문자를 공백 한 칸 `" "`으로 정리하고, `<pre>`와 그 자손 안은 그대로 둔다

## Decision Outcome

Chosen option: "선택지 4: 연속 공백을 한 칸으로 정리 + `<pre>` 예외", because 브라우저도 트리에는 공백을 그대로 저장하고 화면에 그릴 때만 연속된 공백·탭·줄바꿈을 한 칸으로 줄이기 때문이다. Virtual DOM이 이 그리기 규칙을 미리 적용하면 **화면을 결정하는 정보만 남은 트리**가 된다. 그 결과 화면 동일성을 지키면서, 들여쓰기 변경에 Diff가 반응하지 않고, 화면 비교를 코드로 측정할 수 있다.

**1) Virtual DOM 노드 모양**

ADR-0001을 따른다.

| 노드 종류 | 키 | 값 |
|---|---|---|
| 공통 | `type` | 문자열 `"element"` 또는 `"text"` |
| 태그 노드 | `tag` | 소문자 문자열 |
| 태그 노드 | `attrs` | 해시를 쓰고 없으면 `{}` 로 비워둔다. HTML의 `key` 속성은 여기에 넣지 않는다 |
| 태그 노드 | `children` | list of 노드를 쓰고 없으면 `[]` 로 비워둔다 |
| 글자 노드 | `text` | 공백 정리 규칙을 적용한 문자열 |
| 태그 노드 (선택) | `key` | HTML `key` 속성 값. 속성이 없으면 키 자체가 없다 (ADR-0001) |
| 공통 (선택) | `dom` | 실제 영역 변환 시에만 기록하는 실제 노드 참조 (ADR-0001) |

Phase 2의 컴포넌트도 이 모양의 객체를 반환해 Diff/Patch에 넘긴다.

**2) 변환 함수 `dom_to_vdom(실제 노드, 기록 여부)` → Virtual DOM 객체 하나**

- **기록 여부**는 호출하는 쪽이 정하고, 기본값은 "기록 안 함"이다. "기록함"이면 만드는 모든 객체(자손 포함)의 `dom`에 그 객체를 만든 실제 노드를 넣는다.
  - **실제 영역을 처음 변환할 때만** "기록함"으로 부른다. 테스트 영역 변환이나 테스트에서는 기본값을 쓴다. 테스트 영역 노드가 `dom`에 들어가면 Patch가 엉뚱한 영역을 고치기 때문이다.
- 페이지는 루트를 틀의 첫 자식 요소로 찾는다(ADR-0006).
- 글자 노드(`nodeType === 3`, 재귀의 멈추는 조건): 글자를 읽고 공백 정리 규칙을 적용해 `{ type: "text", text }`를 반환한다.
- 태그 노드(`nodeType === 1`):
  - 태그 이름은 `localName`으로 읽는다. `tagName`은 HTML 요소에서 대문자(`"DIV"`)를 돌려주므로 쓰지 않는다.
  - 속성을 읽는다. 이름이 `key`인 속성은 `attrs`에 넣지 않고 `key`에 넣는다.
  - 이름이 `on`으로 시작하는 속성과, 값이 `javascript:`로 시작하는 `href`·`src` 속성은 건너뛴다(4절).
  - `childNodes`를 **순서대로** 처리해 결과를 `children`에 모은 뒤, `{ type: "element", tag, attrs, children }`(그리고 `key`가 있으면 `key`)를 반환한다.
- 그 밖의 노드(주석 등): 부모가 childNodes를 순서대로 돌 때 nodeType이 1(태그) 또는 3(글자)이 아니면 dom_to_vdom을 부르지 않고 건너뛴다. `<script>` 요소도 같은 방식으로 부모가 건너뛴다(4절). 따라서 dom_to_vdom에는 글자 노드와 태그 노드만 들어온다. 주석은 화면에 그려지지 않으므로 화면 동일성에 영향이 없다.
- 결과는 언제나 객체 하나다. 입력이 글자 노드 또는 태그 노드로만 한정되기 때문이다(주석 등은 부모가 미리 거른다).

**3) 공백 정리 규칙**

- **공백 문자**는 다음 다섯 가지로 한정한다: 공백(` `, U+0020), 탭(`\t`), 줄바꿈(`\n`), 캐리지 리턴(`\r`), 폼 피드(`\f`).
  - `&nbsp;`(U+00A0)는 공백 문자가 아니다. 브라우저도 `&nbsp;`는 줄이지 않고 그대로 그린다.
  - 구현할 때 정규식은 문자를 직접 나열한 `/[ \t\n\r\f]+/g`를 쓴다. JavaScript의 `\s`는 `&nbsp;`(U+00A0)까지 공백으로 취급하므로 `/\s+/g`를 쓰면 T8이 실패한다.
- `<pre>`와 그 모든 자손 안의 글자 노드는 그대로 둔다.
- 그 밖의 모든 글자 노드는 공백 문자가 연달아 있는 덩어리를 공백 한 칸 `" "`으로 바꾼다.

**4) 실행되는 내용 건너뛰기 (2026-11-10 추가, CF-04)**

ADR-0006 이후 사용자는 코드 입력칸에 아무 HTML이나 쓸 수 있다(FR-02). 그래서 "`<script>`는 샘플에 없다"는 전제가 사용자 입력에서는 성립하지 않는다. `<script>`를 그대로 두면 미리보기를 `vdom_to_dom`으로 그릴 때와 Patch할 때 실행될 수 있고, e3 때문에 입력이 멈출 때마다 반복될 수 있다. `on*` 속성과 `javascript:` 링크는 클릭하면 실행된다.

| 건너뛰는 것 | 방법 |
|---|---|
| `<script>` 요소 | 부모가 자식을 돌 때 주석처럼 건너뛴다 |
| 이름이 `on`으로 시작하는 속성 (`onclick` 등) | `attrs`에 넣지 않는다 |
| 값이 `javascript:`로 시작하는 `href`·`src` 속성 | `attrs`에 넣지 않는다 |

- 검토한 선택지: s1(그대로 두고 알려진 한계로 기록), s2(변환할 때 건너뛴다).
- Chosen option: **s2**, because 실제 영역과 코드 입력칸 양쪽 모두 `dom_to_vdom`을 거치므로 같은 규칙이 적용되어 기존 동작(ADR-0006 TA1 등)에 문제가 없고, Phase 2 이벤트는 함수로 넘기며 `dom_to_vdom`을 거치지 않으므로 Phase 2에도 문제가 없기 때문이다. `javascript:` 링크도 클릭하면 코드가 실행되는 같은 종류라 함께 막는다.
- 건너뛰기는 반드시 `dom_to_vdom` 안에서 한다. 코드 입력칸 경로에서만 지우면 실제 영역 쪽 트리에는 남고 새 트리에는 없어서, 고친 것이 없는데도 Patch가 그 속성을 지우려 한다.

### Consequences

- Good, because 들여쓰기 길이 변경은 둘 다 `" "`이 되므로 Diff 변화가 없다. 불필요한 Patch가 없다.
- Good, because 첫 Patch 때도 불필요한 조작이 없다. 실제 영역 DOM에는 `"⏎␣␣"`이 남아 있지만, Diff는 정리된 Virtual DOM끼리 비교하므로 이 노드를 바꾸지 않는다.
- Good, because `<b>안녕</b>⏎<i>하세요</i>`의 줄바꿈도 `" "`으로 남아 화면이 "안녕 하세요"로 유지된다.
- Good, because `<pre>` 안의 빈 줄과 들여쓰기가 보존된다.
- Good, because 부모가 주석 등을 미리 거르므로 dom_to_vdom은 언제나 객체 하나를 반환하고, children에 undefined나 null이 들어가지 않는다. 이후 vdom_to_dom·Diff에서 빈 값 검사가 필요 없다.
- Good, because `key`를 `attrs`에서 빼므로 속성 비교에 짝짓기 정보가 섞이지 않는다.
- Bad, because 변환 결과의 글자가 실제 DOM과 글자 단위로 같지 않다. 실제 DOM과 Virtual DOM의 **같은 구조**를 **화면에 보이는 모습이 같음**으로 재정의해야 한다. (ADR-0001의 Decision Driver도 이에 맞춰 수정했다.)
- Bad, because 없던 자리에 공백이 새로 생기면 `" "` 노드가 끼어든다. 공백 노드에는 `key`가 없으므로 key 없는 자식끼리 순서대로 짝지을 때 밀림이 생길 수 있다. 이는 ADR-0004에서 알려진 한계로 남겼다.
- Bad, because 재귀 깊이가 트리 깊이와 같다. 아주 깊게 중첩된 구조에서는 JavaScript 호출 스택 한계에 닿을 수 있다.
- Bad, because `<pre>` 외에 공백이 의미를 갖는 요소(`<textarea>`, `<style>`, CSS `white-space`)는 이번 과제 범위에서 다루지 않는다. 샘플 HTML에 이런 요소가 없다는 것이 전제다. (`<script>`는 4절에 따라 건너뛴다.)
- Good, because 사용자가 코드 입력칸에 넣은 `<script>`, `on*` 속성, `javascript:` 링크가 미리보기와 실제 영역에서 실행되지 않는다(4절).
- Bad, because FR-02 "자유롭게 수정"에 `<script>`, `on*`, `javascript:` 링크라는 예외가 생긴다(4절).
- Neutral, because 실제 영역 샘플에 `<script>`가 있으면 실제 DOM에는 남고 Virtual DOM에는 없다. 주석과 마찬가지로 Patch는 `dom`으로 노드를 찾으므로 영향이 없다(4절).
- Bad, because SVG 요소 중 일부(`linearGradient` 등)는 `localName`이 대문자를 포함하므로 "모든 `tag`는 소문자"(T11)가 성립하지 않는다. SVG는 이번 과제 범위에서 다루지 않는다.
- Neutral, because 실제 영역의 원래 DOM에는 주석 노드가 남아 있어 실제 DOM 자식과 Virtual DOM 자식의 자리 번호가 어긋난다. 그러나 Patch는 자리 번호가 아니라 `dom`으로 실제 노드를 찾으므로 영향이 없다(ADR-0004).
- Neutral, because 실제 영역에 있던 주석은 테스트 영역으로 옮겨지지 않는다. 화면에는 영향이 없지만, 개발자 도구로 두 영역을 비교하면 주석 유무가 다르다.

### Confirmation

단위 테스트로 확인한다. `dom_to_vdom`에 정해 둔 입력을 넣고, 기대한 객체가 나오는지 코드로 자동 확인한다. 화면 확인은 기능 테스트로 모든 팀원이 함께 한다.

T1~T12는 기본 모드(`dom` 기록 안 함)로 실행한다.

| # | 입력 | 기대 결과 |
|---|---|---|
| T1 | 들여쓰기된 `div > h1, p` | `div.children` 5개, 공백 노드의 `text`는 `" "` |
| T2 | T1과 같은 HTML의 들여쓰기만 2칸 → 4칸 | T1과 결과 객체가 완전히 같다 |
| T3 | `<b>안녕</b>⏎<i>하세요</i>` | 가운데에 `{ type: "text", text: " " }`가 있다 |
| T4 | `<pre><b>첫째 줄</b>⏎⏎⏎<b>넷째 줄</b></pre>` | 가운데 글자가 `"\n\n\n"` 그대로다 |
| T5 | `<pre>` 안의 `<b>` 자손 글자 | 공백이 정리되지 않는다 |
| T6 | 자식·속성이 없는 태그 | `children: []`, `attrs: {}` |
| T7 | `<div><!-- 메모 --><p>a</p></div>` | `div.children`이 `p` 하나뿐이다. 주석이 들어가지 않는다 |
| T8 | `a&nbsp;&nbsp;b` | `text`가 `"a  b"` 그대로다 |
| T9 | 깊게 중첩된 구조 | 오류 없이 변환된다. 깊이 기준은 이후 다시 회의 후 정한다 |
| T10 | 실제 영역과, 그 결과로 렌더링한 미리보기(ADR-0006) | 두 영역을 각각 변환한 결과가 다섯 키(`type`, `tag`, `attrs`, `text`, `children`) 기준으로 같다 |
| T11 | 실제 영역의 `div`, `h1`, `p` | 모든 태그 노드의 `tag`가 소문자(`"div"`, `"h1"`, `"p"`)다 |
| T12 | `<p>안녕␣␣⇥⏎␣하세요</p>` (공백·탭·줄바꿈이 글자 사이에 섞임) | `text`가 `"안녕 하세요"`다. 공백만 있는 노드가 아니어도 정리된다 |
| T13 | `<div><!-- 메모 --><p>a</p></div>`를 "기록함"으로 변환 | `div.children[0].dom`이 주석이 아니라 실제 `p` 노드이고, 모든 객체(글자 노드 포함)에 `dom`이 있다 |
| T14 | 같은 HTML을 기본 모드로 변환 | 어떤 객체에도 `dom` 키가 없다 |
| T15 | `<ul><li key="a" class="x">a</li><li>b</li></ul>`를 기본 모드로 변환 | 첫 `li`의 `key`가 `"a"`이고 `attrs`가 `{ class: "x" }`다(`key` 없음). 둘째 `li`에는 `key` 키 자체가 없다 |
| S1 | 코드에 `<script>alert(1)</script>` 입력 (4절) | 새 트리에 `script` 노드가 없고, 미리보기에도 없다 |
| S2 | `<button onclick="...">` 입력 (4절) | 그 노드의 `attrs`에 `onclick`이 없다 |
| S3 | `<a href="javascript:...">`와 `<a href="https://...">` 입력 (4절) | 앞의 것만 `href`가 없다 |
| S4 | 실제 영역 샘플에 `onclick`이 있을 때 첫 로드 후 고친 것 없이 Patch (4절) | `changes` 0개 (양쪽 같은 규칙) |


## Pros and Cons of the Options

### 선택지 1: 그대로 보존

- Good, because 실제 DOM과 글자까지 같으므로 기존 실제 DOM과 Virtual DOM의 트리 구조가 같다는 인수 기준을 그대로 만족한다.
- Good, because `</b>␣<i>`의 띄어쓰기가 유지된다.
- Neutral, because 정리 규칙이 없어 구현이 가장 단순하다.
- Bad, because 들여쓰기 한 칸만 바꿔도 Diff가 변경으로 판단해 Patch한다.

### 선택지 2: 공백 전용 노드를 버림

- Good, because 공백 변경에 Diff가 반응하지 않는다.
- Neutral, because 노드 수가 줄어 트리가 읽기 쉬워진다.
- Bad, because `<b>안녕</b>␣<i>하세요</i>`가 "안녕하세요"로 붙는 화면 버그가 생긴다.

### 선택지 3: 줄바꿈 포함 공백만 버림

- Good, because 들여쓰기는 버리고 같은 줄 띄어쓰기는 남겨서, 선택지 1·2의 대표 상황을 모두 처리한다.
- Neutral, because "줄바꿈이 있는가" 하나로 판단하므로 규칙은 짧다.
- Bad, because `<b>안녕</b>⏎<i>하세요</i>`에서 공백이 버려져 "안녕하세요"로 붙는다. 브라우저는 "안녕 하세요"로 그리므로 화면이 달라진다.
- Bad, because 규칙을 모르는 사람에게는 버그처럼 보인다.

### 선택지 4: 한 칸으로 정리 + `<pre>` 예외 (채택)

- Good, because 브라우저의 그리기 규칙과 같아서 화면이 같게 유지된다.
- Good, because 들여쓰기 길이 변경에 Diff가 반응하지 않는다.
- Neutral, because `<pre>` 예외 규칙 하나가 추가된다.
- Bad, because 새로 생긴 공백 노드로 인한 자리 밀림은 해결하지 못한다. ADR-0004에서 key로 대부분의 목록 문제를 풀었지만, key가 없는 공백 노드의 밀림은 알려진 한계로 남았다.
