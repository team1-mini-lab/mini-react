# ADR-0016: `dom_to_vdom`은 건너뛴 노드(주석·`<script>`) 때문에 나란히 남은 글자 노드를 하나로 합친다

## Context and Problem Statement

ADR-0002는 "주석과 `<script>`는 부모가 건너뛴다", "공백 덩어리는 한 칸 `" "`으로 줄인다"를 정했지만, **건너뛴 노드 양옆의 글자 노드가 나란히 남는 경우**는 정하지 않았다.

```html
<div>
  <p>A</p>
  <!-- 메모 -->
  <p>B</p>
</div>
```

| 단계 | `div`의 자식 |
| --- | --- |
| 실제 DOM | `[공백] [p] [공백] [주석] [공백] [p] [공백]` (7개) |
| `dom_to_vdom` (ADR-0002) | `[" "] [p] [" "] [" "] [p] [" "]` (6개, 공백 두 개가 나란히) |
| a3로 코드 → g1로 다시 읽음 | `[" "] [p] [" "] [p] [" "]` (5개, 브라우저가 이어진 공백을 하나로 읽음) |

그래서 화면은 같은데 실제 영역(6개)과 미리보기(5개)가 FR-01 기준으로 다르다. 첫 로드부터 VT-33·VT-37이 실패하고, 고친 것 없이 Patch해도 공백 삭제가 변경으로 잡혀 TA1·H6(k1)이 실패하며, 입력 후 되돌려도 이동 버튼이 꺼진다(H9·H10). 공식 샘플(SDD_final_phase1 7.2)은 P4 시연을 위해 주석을 넣게 되어 있어 **반드시** 생긴다. `a<script>x</script>b`처럼 글자 사이의 `<script>`도 같다(`"a"`, `"b"` → 다시 읽으면 `"ab"`).

구현 버그가 아니다. ADR-0002 규칙대로 짜면 생긴다. jsdom 시제품(`docs/verification/results/prototype/t1-roundtrip.js`)으로 확인했다(실제 영역 자식 15개, 다시 읽은 트리 9개, `equalScreen = false`).

## Decision Drivers

- FR-01·FR-03 인수 기준: 첫 로드와 무수정 Patch에서 두 영역이 같고 변경 0개
- "첫 로드에는 실제 영역을 다시 그리지 않는다"(SDD_final_phase1 3장 원칙)
- P4 시연(실제 영역에 주석이 있어도 Patch가 맞게 동작)을 유지
- `dom` 규칙(ADR-0004)과 F1(ADR-0005)을 되도록 건드리지 않음

## Considered Options

- **u1**. `dom_to_vdom`이 자식을 모은 뒤, 나란히 남은 글자 노드를 하나로 합친다
- **u2**. 샘플에서 주석을 공백 줄 사이에 두지 않는다 (규칙은 그대로)
- **u3**. 첫 로드 때 실제 영역을 정리한다 (`normalize()`·주석 제거) 뒤 변환한다

## Decision Outcome

Chosen option: **u1 + (가) 공백 글자끼리만 합친다** (2026-11-10 채택), because 브라우저가 코드를 다시 읽을 때 하는 일(이어진 글자를 하나로)을 Virtual DOM이 미리 하는 것이라 두 영역이 같은 규칙으로 맞춰지고, 실제 영역을 다시 그리지 않으며, 사용자 입력에도 똑같이 적용되기 때문이다. u2는 사용자가 코드에 주석을 넣으면 그대로 생기고, u3는 첫 로드에 실제 DOM을 바꾸므로 원칙과 P4 시연을 깬다.

### 합치기 규칙 (ADR-0002 2)·4)에 추가)

| 규칙 | 내용 |
| --- | --- |
| 언제 | 부모가 `childNodes`를 돌며 자식을 모은 **뒤**, 결과 배열에서 글자 노드가 두 개 이상 나란히 있을 때 |
| 무엇을 | 원래 글자(공백 정리 **전**)를 이어 붙인 뒤 공백 정리 규칙(ADR-0002 3))을 한 번 적용해 글자 노드 하나로 만든다. `<pre>` 안이면 정리하지 않고 이어 붙이기만 한다 |
| `dom` (기록함 모드) | 합친 노드의 `dom`은 **첫 번째** 실제 글자 노드를 가리킨다. 나머지 실제 글자 노드는 주석처럼 Virtual DOM이 추적하지 않는다 |

### 남는 실제 글자 노드와 Patch (확인 필요)

- 합친 노드가 공백만이면, 추적하지 않는 실제 공백 노드가 남아도 화면은 같다(공백 덩어리는 한 칸으로 그려진다).
- 합친 노드의 글자가 Patch로 바뀌면(`text` 변경) 첫 실제 노드의 `nodeValue`만 바뀌고 나머지 실제 노드의 글자는 화면에 남는다. **공백이 아닌 글자가 합쳐진 경우**(`a<script>x</script>b`)에는 화면이 달라질 수 있다.
- 그래서 함께 정할 것: (가) 합치기를 **공백 글자끼리만** 한다(실제 영역 샘플·사용자 코드 대부분이 이 경우) / (나) 공백 아닌 글자도 합치고, Patch의 `text` 변경 때 추적하지 않는 형제 글자 노드를 함께 지운다(ADR-0005 수정 필요).

### Consequences

- Good, because 공식 샘플에서 첫 로드부터 FR-01이 성립하고 무수정 Patch가 변경 0개가 된다.
- Good, because 실제 영역을 다시 그리지 않고, 사용자 코드에도 같은 규칙이 적용된다.
- Bad, because 실제 DOM의 글자 노드와 Virtual DOM 글자 노드가 1:1이 아니게 된다(주석과 같은 종류의 "추적하지 않는 노드"가 생긴다).
- Bad, because (나)를 고르면 Patch에 형제 글자 노드 정리 규칙이 더해진다.
