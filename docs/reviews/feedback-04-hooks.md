# 설계 피드백 04: useState (#39) + useEffect (#40) + useMemo (#41)


- 검토 대상: SDD 4.2 `HookSlot`·렌더링 순서의 Hook 부분, 4.3 Hooks, 5장 Hook 관련 행, 부록 A Hook 행
- 기준 문서: 리액트 issue.md(0번 표 useState·useEffect·useMemo, FR-15~FR-18, C-05~C-07), ADR-0001~0006, ADR-0015
- 공통 사항(issue.md 기준, ADR 통합 번호표)은 피드백 01의 0절과 같다.

## 1. 결론 요약

| 결정 | 내용 | 이유 |
|---|---|---|
| 의존성 목록을 생략한 useEffect | **f1** (리액트와 같게): 생략하면 렌더링마다, 빈 목록 `[]`이면 첫 표시 뒤 한 번만, 목록이 있으면 값이 바뀔 때만 실행한다 | 비용이 없고 실제 리액트와의 차이가 줄어든다. issue.md FR-17의 "지정한 값이 없으면 한 번만"은 이 부분을 설계하기 전에 쓴 문장이라 고친다 |
| effect 정리 함수(cleanup) | **g1**: effect가 함수를 돌려주면 저장했다가, 그 effect를 다시 실행하기 직전에 부른다 | 작은 비용으로 리액트와 같은 동작을 얻고, 타이머 같은 effect를 안전하게 쓸 수 있다 |

## 2. 그대로 가져갈 것

| SDD 설계 | 평가 |
|---|---|
| Hook 저장 칸 배열 `hooks`와 호출 순서 번호 `hookIndex`. 칸마다 종류(`state`·`effect`·`memo`)를 적는다 (4.2) | C-05(hooks 배열), FR-15(다시 계산해도 값 유지), FR-16(여러 상태가 섞이지 않음)을 지킨다. 종류 기록은 Hook 규칙 검사(피드백 05)에 쓴다 |
| useState: 첫 렌더링에 초깃값(함수면 실행 결과) 저장, 다시 렌더링하면 칸의 값을 돌려줌 (4.3) | FR-15. 과제 핵심 질문 "함수는 매번 새로 실행되는데, 상태는 어떻게 유지할까?"의 답이다 |
| setter: 새 값 계산(함수면 이전 값으로 실행) → 이전 값과 `Object.is`로 같으면 무시 → 다르면 저장 후 다시 그리기 예약 (4.3) | 같은 값일 때 다시 그리지 않아 NFR-01에 맞다. 다시 그리기 예약 시점은 피드백 05(Batching)에서 정한다 |
| setter는 렌더링마다 같은 함수를 돌려준다 (4.3) | 핸들러 바꿔 끼우기(ADR-0015)와 충돌하지 않는다 |
| useMemo: 의존성 목록이 그대로면 저장된 결과를 돌려주고, 바뀌면 다시 계산 (4.3) | FR-18 그대로다 |
| 의존성 비교 `depsChanged`: 이전 목록이 없거나, 길이가 다르거나, 같은 자리 값이 `Object.is`로 하나라도 다르면 "바뀜" (4.3) | 결과가 하나로 정해지는 규칙이다 |
| useEffect를 Patch 직후 동기적으로 실행 (4.3) | FR-17 "화면 갱신이 끝난 뒤"를 지킨다. 실제 리액트는 화면을 그린 뒤 조금 늦게 실행한다. "실제 리액트와의 차이점"으로 설명한다 |
| effect 하나가 오류를 내도 다른 effect는 계속 실행하고 `console.error`로 남긴다 (5장) | 한 effect의 실수로 화면 전체가 멈추지 않는다 |

## 3. 고칠 것

### 3-1. FR-17과 의존성 목록 생략 (f1)

| | SDD | issue.md (지금) | 수정 |
|---|---|---|---|
| `useEffect(f)` 생략 | 렌더링마다 | "지정한 값이 없으면 첫 표시 뒤 한 번만" | **렌더링마다** (SDD 그대로) |
| `useEffect(f, [])` | 처음 한 번 | 0번 표: "목록이 비어 있으면 처음 한 번만" | 처음 한 번 (그대로) |
| `useEffect(f, [a])` | `a`가 바뀔 때만 | 바뀌었을 때만 | 그대로 |

issue.md FR-17을 6절처럼 고친다.

### 3-2. Phase 1 쪽 호출 모양

- SDD 4.2 렌더링 순서 5단계의 `createElement`, `applyPatches`는 ADR-0015 2절의 `mount`·`update` 흐름으로 바꾼다.
- effect는 그 흐름(Patch, `dom` 복사·기록, 핸들러 바꿔 끼우기)이 모두 끝난 뒤 실행한다.
- Patch 실패 복구(ADR-0005 6절)가 일어난 경우에도 effect는 실행한다. 화면은 새 트리대로 갱신되었기 때문이다.

## 4. 추가할 것

### 4-1. effect 실행 순서 (g1 포함)

렌더링 한 번이 끝난 뒤, effect 칸을 앞에서부터 차례로 보며:

1. 이번 렌더링에서 실행하기로 정해진 effect인가? (생략 → 항상 / `[]` → 첫 렌더링만 / 목록 → `depsChanged`일 때)
2. 그렇다면, 이전 실행이 남긴 정리 함수가 있으면 먼저 부른다.
3. effect를 실행하고, 돌려준 값이 함수면 정리 함수로 칸에 저장한다.

- 정리 함수는 "다시 실행하기 직전"에만 부른다. `unmount()`가 없으므로(ADR-0015) 컴포넌트가 내려갈 때 부르는 경우는 없다.

### 4-2. 알려진 한계

| 한계 | 설명 |
|---|---|
| 의존성 목록에 렌더링마다 새로 만드는 객체·배열을 넣으면 항상 "바뀜" | `Object.is`는 같은 객체일 때만 같다고 본다. 실제 리액트도 같다 |
| effect 안에서 상태를 바꾸면 다시 렌더링 → effect 재실행이 반복될 수 있음 | 안전장치(연속 실행 횟수 제한)는 Batching과 함께 피드백 05에서 정한다 |

## 6. 문서 변경

| 대상 | 변경 |
|---|---|
| issue.md FR-17 요구사항 | "…지정한 값이 이전과 달라졌을 때만 실행해야 한다. 지정한 값이 없으면 첫 표시 뒤 한 번만 실행해야 한다." → "…지정한 값이 이전과 달라졌을 때만 실행해야 한다. **값 목록을 비워 두면 첫 표시 뒤 한 번만, 목록 자체를 생략하면 화면을 다시 계산할 때마다** 실행해야 한다. 작업이 정리 함수를 돌려주면 다음 실행 직전에 그 함수를 먼저 실행해야 한다." |

| SDD 4.2, 4.3, 5장, 부록 A | 2~5절 반영 |

## 7. 테스트 후보

결정마다 그 결정이 깨졌을 때 잡아낼 테스트를 하나 이상 두었다. 아래 K1~K14를 모두 채택한다.

| # | 상황 | 기대 결과 | 출처 |
|---|---|---|---|
| K1 | `useState(5)`, `useState(() => 7)` | 값 5, 7. setter는 함수 | useState |
| K2 | setter로 0 → 1 바꾼 뒤 다시 렌더링 | 1이 보임 | FR-15 |
| K3 | 상태 두 개를 각각 바꾼 뒤 다시 렌더링 | 각자의 값이 유지됨 | FR-16 |
| K4 | setter에 지금과 같은 값 | 다시 렌더링 없음 | setter 규칙 |
| K5 | `setCount(c => c + 1)` | 이전 값에 1을 더한 값 | setter 규칙 |
| K6 | 렌더링 두 번 | 두 번 받은 setter가 같은 함수 | setter 규칙 |
| K7 | 목록 생략 effect, 렌더링 3번 | 3번 실행 | f1 |
| K8 | `[]` effect, 렌더링 3번 | 1번 실행 | f1, FR-17 |
| K9 | `[a]` effect, 렌더링 3번 중 2번째에만 `a` 변경 | 2번 실행 (첫 렌더링 + 2번째) | FR-17 |
| K10 | effect 안에서 실제 DOM 읽기 | 이번 렌더링의 새 값이 이미 화면에 있음 | FR-17 "화면 갱신 뒤" |
| K11 | 정리 함수를 돌려주는 `[a]` effect, `a`를 두 번 바꿈 | 정리 함수가 다음 실행 직전마다 1번씩, 첫 실행 전에는 0번 | g1 |
| K12 | `useMemo(spy, [a])`, `a` 그대로 다시 렌더링 → `a` 변경 | spy 호출 1번 → 2번 | FR-18 |
| K13 | useMemo 결과를 같은 렌더링 안에서 화면에 씀 | 화면에 계산 결과가 보임 | FR-18 "화면을 계산하는 도중에 제공" |
| K14 | effect 두 개 중 첫 번째가 오류 | 두 번째도 실행되고 `console.error` 1번 | 2절 |
