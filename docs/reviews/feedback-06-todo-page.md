## 3. 고칠 것

### 3-1. `DebugPanel`의 변경 목록 표시

우리 `changes`는 dict 객체를 가리켜 그대로 보여 주면 트리 전체가 쏟아진다. ADR-0006 8-1절의 요약 한 줄 형식을 쓴다.

## 4. 추가할 것

### 4-1. 목록 항목에 `key` (ADR-0015 추가)

- SDD에는 `TodoItem`에 `key`를 붙인다는 말이 없다. `key`가 없으면 Diff가 자리 순서로 짝을 짓는다(ADR-0004). 첫 번째 할 일을 지우면 뒤의 줄 글자가 모두 바뀌고 마지막 줄이 삭제되어 조작이 여러 번 일어난다. `key`가 있으면 삭제 1번이다.
- `TodoItem`에 할 일 id를 `key`로 넘긴다: `h(TodoItem, { key: todo.id, todo, ... })`
- **ADR-0015에 빠져 있던 규칙**: 컴포넌트에 준 `key`는 컴포넌트 함수의 props로 넘기지 않고, 펼친 결과의 루트 노드의 `key`로 붙인다. 컴포넌트를 바로 펼치므로(ADR-0015) 그대로 두면 `key`가 사라지기 때문이다. 실제 리액트도 `key`를 props로 전달하지 않는다. → ADR-0015 1절에 추가했다.

### 4-2. 입력칸 `value`와 체크박스 `checked` (ADR-0004 추가)

- 할 일을 추가하면 입력칸을 비운다(`setInput("")`). 새 트리의 `attrs.value`가 `""`이 되어 Patch가 `setAttribute("value", "")`를 해도, 속성은 "처음 값"일 뿐이라 사용자가 이미 친 **지금 값**은 그대로 남는다. 체크박스 `checked`도 같다.
- SDD 3.4 `setProp`이 이미 이 문제를 다뤘다(`value`·`checked`는 property로 쓰고, 같으면 쓰지 않음). 우리 Phase 1 설계(ADR-0003·0004의 `setAttribute`)에는 없었다.
- **수정**: Patch의 속성 수정에서 `value`·`checked`는 지금 값(property)도 함께 바꾸고, 이미 같으면 건드리지 않는다(같은 값을 다시 쓰면 커서가 튈 수 있다). → ADR-0004 1절에 추가했다.
- Phase 1 P2("바나나 입력칸의 3이 그대로")는 그 입력칸의 `attrs`가 바뀌지 않으므로 영향이 없다.
- 이 브라우저 동작은 구현 때 테스트(TD3·TD5)로 확인한다.

### 4-3. Todo 앱의 Patch 하이라이트

ADR-0006 8-3절의 공통 하이라이트를 켜고, 강조하지 않을 태그 목록에 `input`, `textarea`를 넣는다. 체크 하나를 누르면 그 줄만 반짝이고, 타이핑해도 입력칸은 반짝이지 않는다.
