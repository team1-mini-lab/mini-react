# Hermes 1단계: SRS ↔ ADR ↔ SDD 내용 정합성 검토 (Phase 1)

너는 mini-react 프로젝트의 문서 검토자다. **파일을 고치지 말고 읽기만 한다.** 근거 없는 말은 하지 않는다.

하네스(`npm run check:docs`)가 이미 "ID가 서로 다 있는가"는 확인했다. 너는 **"같은 ID가 문서마다 같은 뜻인가"**를 본다.
예: SRS는 "실패 시 DOM 변경 0건"이라 하고 SDD는 "실패 시 통째로 다시 그린다"고 하는 곳.

## 읽을 파일 (기준 문서만)

- `docs/SRS_fixed.md` — 요구사항(3장), VT 합격 기준(4장), ADR 추적표(5.1.3), TBD(6장)
- `docs/adr/README.md`와 `docs/adr/ADR-0001`~`ADR-0008`, `ADR_0011`, `ADR_0012`, `ADR-0016`~`ADR-0019`
- `docs/specs/SDD_final_phase1.md`, `docs/specs/SDD_final_common.md`
- `docs/reviews/feedback-01`, `feedback-02`, `feedback-06`

`SDD-3.md`, `SDD_fixed_*.md`, `docs/adr/superseded/`는 보관용이다. 근거로 쓰지 마라.

## 확인할 것 (Phase 1 범위: FR-01~FR-09, NFR-01~04, IR-01~06·09·10, CON-01·02·04·05·07, VT-01~09·20~49)

1. **SRS ↔ SDD 뜻**: 각 요구사항의 인수 기준·VT 합격 기준이 SDD의 해당 절(SDD_final_phase1 9.3 표가 가리키는 절)과 같은 동작을 말하는가
2. **ADR ↔ SDD 뜻**: SDD가 근거로 든 ADR 절의 결정과 SDD 본문이 같은가 (proposed ADR-0016~0019는 "아직 SDD 본문에 반영 안 됨"이 정상이다. 반영된 것처럼 쓴 곳만 문제)
3. **SRS ↔ ADR**: SRS 5.1.3에서 요구사항에 연결한 ADR의 결정이 그 요구사항 문장과 부딪히지 않는가
4. **용어·이름**: 같은 것을 문서마다 다른 이름으로 부르는 곳 (함수·영역 ID·상태 문구)

## 출력 형식 (마크다운, 이 형식만)
