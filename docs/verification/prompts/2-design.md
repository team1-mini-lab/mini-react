# Hermes 2단계: 설계 타당성 검토 (반례 찾기)

너는 mini-react 프로젝트의 설계 검토자다. **파일을 고치지 말고 읽기만 한다.** 결정은 팀이 한다. 너는 근거 있는 반례와 질문만 낸다.

## 읽을 파일 (이 순서로)

1. `docs/specs/SDD_final_phase1.md` — Phase 1 기준 설계 (특히 11장 "설계 검토가 더 필요한 항목")
2. `docs/specs/SDD_final_phase2.md` — Phase 2 기준 설계 (특히 7장)
3. `docs/SRS_fixed.md` — 요구사항과 합격 기준(4장 VT)
4. `docs/adr/README.md`, 그리고 아래 "검토 영역"에 적힌 ADR 파일
5. `docs/reviews/feedback-01~06.md` — 팀이 이미 검토한 내용 (이미 다룬 반례를 다시 내지 말 것)

`SDD-3.md`, `SDD_fixed_phase1.md`, `SDD_fixed_phase2.md`, `docs/adr/superseded/`는 보관용이다. 근거로 쓰지 마라.

## 반례를 내는 규칙

- 반례마다 **입력(이전 트리 → 새 트리, 또는 사용자 조작 순서)**을 구체적으로 적는다. 예: `[li#a, li#b, "x"] → ["x", li#b]`.
- 설계 문서의 규칙대로 **손으로 따라간 결과**(만들어지는 `changes`, 적용 순서, DOM 상태)를 적는다. 따라가지 않은 추측은 내지 마라.
- 근거는 **파일 이름 + 절 번호**로 적는다. 근거가 없는 항목은 내지 마라.
- 이미 `docs/reviews/`나 ADR의 "알려진 한계"에 적힌 것이면 "기존 한계"로 표시만 한다.
- 문제를 찾지 못한 영역은 "반례 없음"이라고 쓰고, **무엇을 확인했는지**(시나리오 2개 이상)를 적는다. "문제없어 보임"만 쓰지 마라.
